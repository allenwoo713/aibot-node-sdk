# Milestone v1.1 Requirements (Archived)

**Status:** ✅ COMPLETE — archived 2026-04-20
**Milestone:** AI Validation & Persistent Storage

## Active (All Completed)

### AI-API — AI API Validation

- [x] **AIAPI-01**: User receives a validated AI response even when the upstream API returns malformed or empty content blocks — *validated via UAT*
- [x] **AIAPI-02**: User can configure retry policy (maxRetries, base delay, backoff multiplier, jitter) via `BotConfig` — *validated via UAT*
- [x] **AIAPI-03**: Retry logic only retries retryable errors (429, 5xx, timeout) and fails fast on non-retryable errors (400, 401, 403, 404, 422) — *validated via UAT*
- [x] **AIAPI-04**: SDK surfaces structured error classification (retryable, rate_limited, auth_invalid, unknown) for operator observability — *validated via UAT*
- [x] **AIAPI-05**: Token usage is tracked and forwarded in `ChatResult` when the API returns it — *validated via UAT*
- [x] **AIAPI-06**: Input payloads exceeding `maxInputTokens` are rejected or truncated before the API call to prevent runaway costs — *validated by unit tests*

### PERS — Persistent Conversation Storage

- [x] **PERS-01**: `ConversationStore` constructor accepts an optional pluggable `PersistenceBackend` while defaulting to existing JSON behavior — *validated via UAT*
- [x] **PERS-02**: Existing JSON persistence logic is extracted into `JsonFileBackend` without behavior changes — *validated via UAT*
- [x] **PERS-03**: A new `SqliteBackend` implements `PersistenceBackend` using SQLite with WAL mode and serialized writes — *validated via UAT*
- [x] **PERS-04**: `ConversationStore.get()` remains synchronous by keeping an in-memory LRU cache in front of the backend — *validated via UAT*
- [x] **PERS-05**: Existing `.bot-state.json` files are automatically migrated into SQLite on first startup when the DB is empty — *validated by unit tests*
- [x] **PERS-06**: All persistence backends are covered by dedicated unit tests and run through shared behavior assertions — *validated via UAT*

### INTEG — Integration & Deployment

- [x] **INTEG-01**: `BotOrchestrator.stop()` closes the persistence backend connection before exiting — *validated via UAT*
- [x] **INTEG-02**: `entry.ts` graceful shutdown is async and awaits `bot.stop()` on SIGINT/SIGTERM — *validated via UAT*
- [x] **INTEG-03**: Docker image builds successfully with the chosen SQLite dependency — *validated via UAT*
- [x] **INTEG-04**: Full test suite (existing + new) passes; coverage does not regress below current levels — *validated via UAT*

## Out of Scope

| ID | Item | Reason |
|----|------|--------|
| OOS-01 | MongoDB backend implementation | SQLite satisfies single-node SDK needs; MongoDB remains a future differentiator |
| OOS-02 | Real-time streaming token validation | Complexity outweighs reliability gain for v1.1 |
| OOS-03 | Per-conversation budget ceiling / cost tracking across days | Requires product decisions and cumulative accounting beyond v1.1 scope |
| OOS-04 | Built-in prompt injection detection / content moderation | Rely on Anthropic safety filters; out of SDK scope |
| OOS-05 | Encryption-at-rest inside the SDK | Operational concern; rely on filesystem/DB-native protections |
| OOS-06 | Automatic model fallback across vendors | `AiBackend` interface already allows consumers to plug their own |
