# Milestone v1.1: AI Validation & Persistent Storage

**Status:** ✅ SHIPPED 2026-04-20
**Phases:** 4–6
**Total Plans:** 8

## Overview

Strengthen AI call reliability with validation, retries, and cost guards, while replacing JSON-based conversation persistence with a robust database-backed store. All persistence classes exported via SDK public API. Docker image production-ready with better-sqlite3 native addon support.

## Phases

### Phase 4: AI API Validation & Reliability

**Goal**: Developers can rely on robust AI call handling with validation, retries, and cost guards
**Depends on**: Nothing (first phase of v1.1)
**Plans**: 3 plans

Plans:

- [x] 04-01: Config contracts and ChatResult extension
- [x] 04-02: Core adapter implementation (retry, validation, classification, truncation)
- [x] 04-03: Bot orchestrator integration and full test suite verification

**Details:**
Extended type contracts for retry policies, fallback messages, token limits, and structured error classification. Rewrote AnthropicApiAdapter with configurable retry logic, response validation, error classification, token tracking, and input truncation. Wired ChatResult.errorCode through BotOrchestrator with proper logging.

### Phase 5: Persistent Conversation Storage

**Goal**: Developers can replace JSON file persistence with a robust SQLite-backed store without breaking existing consumers
**Depends on**: Nothing (parallel to Phase 4)
**Plans**: 3 plans

Plans:

- [x] 05-01: PersistenceBackend interface + JsonFileBackend + SqliteBackend
- [x] 05-02: Refactor ConversationStore with pluggable backend
- [x] 05-03: Async lifecycle wiring + comprehensive tests

**Details:**
Created pluggable persistence layer with PersistenceBackend interface, JsonFileBackend (atomic file writes), and SqliteBackend (better-sqlite3 with WAL mode). Refactored ConversationStore to delegate through backend interface while preserving sync get(), TTL, LRU, sliding window. Wired async shutdown lifecycle through bot stack. Comprehensive test coverage: parameterized backend tests + SQLite-specific tests.

### Phase 6: Integration & Deployment

**Goal**: The bot service deploys reliably with the new SQLite dependency and the SDK public API exposes the persistence layer
**Depends on**: Phase 4, Phase 5

Fixed Dockerfile production stage to copy node_modules (with native addon) from builder stage instead of reinstalling. Exported persistence classes from SDK public API (src/index.ts). Verified Docker image builds end-to-end. Full test suite passes (98/98) with no regressions.

## Milestone Summary

**Key Decisions:**

- AI retry defaults: maxRetries=1, retryBaseDelayMs=2000, retryBackoffMultiplier=2, retryJitter=true
- maxInputTokens=8192 with character-count/4 heuristic for truncation
- Disable Anthropic SDK built-in retry (maxRetries: 0) to avoid double retry layers
- better-sqlite3 with WAL mode for production SQLite persistence
- Migration renames (not deletes) original JSON file for safety
- Fallback messages are in Chinese to match existing UX

**Issues Resolved:**

- FallbackTransport.isDuplicate() dropped 'message.text' events — fixed with `${msgid}:${eventName}` dedup key
- Docker image lost data on restart — fixed with `VOLUME ["/app/data"]` + `ENV PERSISTENCE_PATH`
- pnpm 10 blocked better-sqlite3 build scripts — fixed with `onlyBuiltDependencies` config
- ESM module resolution failure in Docker — fixed with `node-linker hoisted`

**Issues Deferred:**

- Dockerfile production stage copies full node_modules including devDependencies (suboptimal image size)
- gracefulShutdown lacks error handling for bot.stop() failures
- transport.stop() not awaited in BotOrchestrator.stop() (future-proofing)

**Technical Debt Incurred:**

- AIAPI-06 and PERS-05 verified by unit tests only; no dedicated E2E/UAT coverage
- No VERIFICATION.md files (UAT.md used instead)
- No Nyquist validation for any phase
- REQUIREMENTS.md traceability table missing INTEG-05 for SDK public API exports
