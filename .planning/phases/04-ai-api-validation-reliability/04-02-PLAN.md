    Rewrite src/ai/api-adapter.ts with the following changes. Preserve the existing import style and export.

    **Constructor changes:**
    - Add 9 new private fields matching the new BotConfig fields: maxInputTokens, maxRetries, retryBaseDelayMs, retryBackoffMultiplier, retryJitter, fallbackRateLimit, fallbackAuthInvalid, fallbackValidationFailed, fallbackRetryable
    - Update the Pick<BotConfig, ...> type in the constructor to include all new fields
    - Set `this.client = new Anthropic({ apiKey: config.anthropicApiKey, baseURL: config.anthropicBaseUrl, maxRetries: 0 })` — maxRetries: 0 disables SDK built-in retry

    **New private method: classifyError(err: any)**
    Returns an object `{ errorCode: ChatResult['errorCode'], retryable: boolean, fallbackMessage: string }`:
    - status === 429 → errorCode: 'rate_limited', retryable: true, fallbackMessage: this.fallbackRateLimit
    - status >= 500 → errorCode: 'retryable', retryable: true, fallbackMessage: this.fallbackRetryable
    - err?.code === 'ETIMEDOUT' || err?.code === 'ECONNRESET' || err?.code === 'ENOTFOUND' || err instanceof Error && err.message?.toLowerCase().includes('timeout') → errorCode: 'retryable', retryable: true, fallbackMessage: this.fallbackRetryable
    - status === 401 → errorCode: 'auth_invalid', retryable: false, fallbackMessage: this.fallbackAuthInvalid
    - status === 400 || status === 403 || status === 404 || status === 422 → errorCode: 'unknown', retryable: false, fallbackMessage: this.fallbackRetryable
    - default → errorCode: 'unknown', retryable: false, fallbackMessage: this.fallbackRetryable

    **New private method: validateResponse(response: Anthropic.Messages.Message)**
    Returns `{ valid: boolean; content: string }`:
    - If !response.content || response.content.length === 0 → valid: false
    - Filter content blocks where type === 'text', map to .text, join('')
    - If joined text is empty or /^\s*$/.test(text) → valid: false
    - Else → valid: true, content: text

    **New private method: calculateDelay(attempt: number)**
    - base = this.retryBaseDelayMs * (this.retryBackoffMultiplier ** attempt)
    - If this.retryJitter → multiply by (0.5 + Math.random() * 0.5) (jitter between 0.5x and 1.0x)
    - Return Math.round(base)

    **Rewrite chat() method:**
    1. Build messages array as before (filter system, ensure latest user message)
    2. Call new private method `truncateMessages(messages)` to enforce maxInputTokens
    3. Loop attempt from 0 to this.maxRetries (inclusive: attempt 0 is first call, attempts 1..maxRetries are retries)
    4. Inside loop: call `this.client.messages.create(..., { timeout: this.timeoutMs })`
    5. On success: call validateResponse(response)
       - If valid: return { content, usage: { input_tokens, output_tokens } if present }
       - If invalid: return { content: this.fallbackValidationFailed, error: true, errorCode: 'validation_failed' }
    6. On error: call classifyError(err)
       - If retryable AND attempt < this.maxRetries: await delay(calculateDelay(attempt)), continue loop
       - Else: return { content: fallbackMessage, error: true, errorCode }

    **New private method: truncateMessages(messages: Anthropic.Messages.MessageParam[])**
    - Estimate tokens per message using character-count heuristic: `Math.ceil(content.length / 4)` where content is the message text
    - Sum tokens from all messages
    - If total <= this.maxInputTokens: return messages unchanged
    - Else: drop oldest messages (from index 0) until total <= this.maxInputTokens, BUT never drop the last message (the current user message)
    - If even the last message alone exceeds maxInputTokens, return only the last message (preserving it is required per D-01)
    - Return the truncated array

    **Preserve existing behavior:**
    - System prompt selection based on contactType
    - Usage forwarding when API returns it
    - The `delay` helper function stays as-is

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-03 | Information Disclosure | classifyError | mitigate | Do not include raw err.message in ChatResult.content; use configured fallback messages per D-08 |
| T-4-04 | Denial of Service | retry loop | mitigate | Cap maxRetries at config value (default 1 per D-03); disable SDK built-in retry (maxRetries: 0) to avoid double retry layers |
| T-4-05 | Denial of Service | truncateMessages | mitigate | Enforce maxInputTokens before API call to prevent runaway costs; never drop the current user message per D-01 |
| T-4-06 | Tampering | validateResponse | mitigate | Reject empty/whitespace-only responses to prevent downstream processing of malformed data |
</threat_model>
