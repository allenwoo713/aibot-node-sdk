    Create `src/token-manager.ts` with a `TokenManager` class:
    - Constructor: `constructor(options: { corpId: string; secret: string; tokenFilePath: string; logger: Logger; httpClient: AxiosInstance })`
    - Private fields:
      - `inMemToken: TokenCache | null = null`
      - `fetchPromise: Promise<string> | null = null` (deduplication lock)
      - `refreshTimer: ReturnType<typeof setTimeout> | null = null`
      - `corpId`, `secret`, `tokenFilePath`, `logger`, `httpClient`
    - Private static readonly `GET_TOKEN_URL = 'https://qyapi.weixin.qq.com/cgi-bin/gettoken'`
    - Private static readonly `PROACTIVE_BUFFER_MS = 5 * 60 * 1000` (5 minutes)
    - Method `async getToken(): Promise<string>`:
      1. If `inMemToken` exists and `Date.now() < inMemToken.expires_at - PROACTIVE_BUFFER_MS`, return `inMemToken.access_token`
      2. Try loading from token file: read file at `tokenFilePath`, parse JSON as `TokenCache`. If valid (not expired with buffer), set `inMemToken` and return `access_token`
      3. If file read fails (missing, corrupt, parse error), log warning and continue — do NOT throw (per D-03)
      4. Deduplicate concurrent fetches: if `fetchPromise` exists, return `await fetchPromise`
      5. Otherwise set `fetchPromise = this.doFetch().finally(() => { this.fetchPromise = null; })` and return it
    - Private method `async doFetch(): Promise<string>`:
      1. Call `this.httpClient.get(TokenManager.GET_TOKEN_URL, { params: { corpid: this.corpId, corpsecret: this.secret } })`
      2. Validate response: `errcode === 0`, `access_token` and `expires_in` present
      3. Compute `expires_at = Date.now() + expires_in * 1000`
      4. Set `this.inMemToken = { access_token, expires_at }`
      5. Persist to file atomically: write JSON to `${tokenFilePath}.tmp`, then `fs.rename()` to `tokenFilePath`. On Windows, write directly (no rename). Use `fs/promises` async I/O. Write with mode `0o600` on non-Windows.
      6. Schedule proactive refresh: `this.scheduleRefresh(expires_at)`
      7. Return `access_token`
      8. On any fetch error, log error and throw with message including errcode/errmsg
    - Method `async forceRefresh(): Promise<string>`:
      1. Clear `inMemToken` to null
      2. Call and return `this.getToken()` (which will fetch a new token)
    - Private method `scheduleRefresh(expiresAt: number): void`:
      1. If `refreshTimer` exists, `clearTimeout(this.refreshTimer)`
      2. Compute `delay = Math.max(0, expiresAt - Date.now() - PROACTIVE_BUFFER_MS)`
      3. Set `refreshTimer = setTimeout(() => this.refreshToken(), delay)`
    - Private method `async refreshToken(): Promise<void>`:
      1. Log info that proactive refresh is starting
      2. Call `this.doFetch()` to get new token
      3. On error, log warning — old token remains usable, next API call will trigger reactive recovery (per D-07)
    - Method `stop(): void`:
      1. If `refreshTimer` exists, `clearTimeout(this.refreshTimer)` and set to null
      2. This prevents setTimeout leaks on client destruction (per Pitfall 5 in RESEARCH.md)

    Important implementation details:
    - Use `import fs from 'fs/promises'` for all file I/O
    - Never log the actual `access_token` value — log only masked prefix or expiry status (per security threat model)
    - Token file format: `{"access_token":"...","expires_at":1234567890123}`

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SDK → WeCom Open Platform | Untrusted network; bearer token crosses this boundary |
| Token file → File system | Token persisted to disk; other processes may read |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-7-01 | Information Disclosure | TokenManager logs | mitigate | Never log `access_token` value; log only expiry status or masked prefix. Verify: grep token-manager.ts for `access_token` in log calls — must not appear. |
| T-7-02 | Information Disclosure | Token file on disk | mitigate | Write token file with mode `0o600` (owner read/write only) on non-Windows. Verify: `fs.writeFile(path, data, { mode: 0o600 })` appears in token-manager.ts. |
| T-7-03 | Tampering | Replay of expired token | mitigate | Proactive refresh (5 min buffer) + reactive retry on 40014/40001. Both implemented in TokenManager and request(). |
| T-7-04 | Spoofing | SSRF via endpoint param | mitigate | `request()` validates `endpoint.startsWith('/')` and `!endpoint.includes('..')` before making request. |
</threat_model>
